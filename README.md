# 종로M READING WORKBOOK 제작기

이 프로그램은 **영어 지문 워크북 제작만** 합니다. WEEKLY TEST, SIMUL TEST, VOCA 기능은 포함하지 않습니다.

## 실행

Node.js 20 이상을 설치한 뒤, 이 폴더에서 실행하세요.

```bash
npm install
export OPENAI_API_KEY="본인의_API_키"
npm start
```

Windows PowerShell에서는 `export` 대신 `$env:OPENAI_API_KEY="본인의_API_키"`를 사용합니다. 브라우저에서 `http://localhost:3000`에 접속하세요.

Render에서는 이 폴더 내용을 저장소 최상위에 올리고 **Node 웹 서비스**로 만드세요. Build Command는 `npm install`, Start Command는 `npm start`입니다. 환경변수 `OPENAI_API_KEY`를 등록하세요. 기존 Python 앱 저장소를 그대로 사용할 경우에는 서비스의 런타임과 저장소 구성을 Node용으로 바꿔야 합니다.

선택 환경변수: `OPENAI_WORKBOOK_MODEL`(기본 `gpt-5-mini`), `OPENAI_IMAGE_MODEL`(기본 `gpt-image-2.5-flare`). 이미지 모델은 `2016x672` 크기의 **가로 3:1** 출력과 이미지 참조 편집을 지원해야 합니다. 이전 배포에서 `OPENAI_IMAGE_MODEL=gpt-image-1-mini`를 지정했다면 이 값을 제거하거나 가로형 출력을 지원하는 모델로 바꾸세요. API 키는 서버에만 두며 브라우저에 입력하지 않습니다.

## 제작 순서

1. **교과서** 또는 **모의고사 18–45번**을 선택합니다.
   - 교과서는 1문단·2문단 입력 칸에 각각 문단을 넣고 필요하면 **+ 문단 추가**를 누릅니다. 빈 문단은 건너뜁니다.
   - 모의고사는 원하는 번호의 칸을 펼쳐 영어 본문을 넣습니다. **18번과 45번만 입력하면 그 두 번호만 생성**합니다. 각 번호는 독립 지문으로 처리되며, 빈 줄이 있어도 번호 안에서는 한 지문입니다. 입력하지 않은 번호는 분석·삽화·인쇄 결과에서 모두 제외됩니다.
2. 소제목(교과서)이나 우리말 해석(선택)을 입력합니다. 해석을 비우면 AI가 작성합니다. PDF, DOCX, TXT, MD 파일을 칸별로 불러올 수 있습니다.
3. **워크북 생성**을 누릅니다. 지문 분석은 최대 2개, 삽화는 최대 2개를 동시에 처리합니다. 완성된 지문의 그림을 다른 지문 분석과 겹쳐 생성합니다. 일시적인 API 오류는 자동으로 간격을 두고 재시도합니다. 한 번호만 실패해도 다른 번호의 완성본은 보존하며, **실패한 항목 다시 만들기**로 해당 번호와 누락된 삽화를 재시도할 수 있습니다.
4. 완성되면 **학생용 PDF 저장**과 **교사용 PDF 저장**을 각각 눌러 브라우저 인쇄 대상에서 **PDF로 저장**을 선택합니다. 여러 번호를 입력하면 한 파일에 번호순으로 묶고, 모든 페이지에 해당 번호를 표시합니다.

## 워크북 구성

- **READING:** 문단마다 페이지당 3문장을 기본으로 배치합니다. 마지막에 1~2문장이 남으면 직전 페이지에 합쳐 마지막 페이지를 4~5문장으로 만듭니다(7문장 → 3+4, 8문장 → 3+5). **3컷 삽화**가 기본이며, 4~5문장도 세 컷에 빠짐없이 묶어 표현합니다. 1~2문장만 있는 문단은 그 수에 맞춰 컷을 만듭니다. 각 문장과 해석 사이에 **앞 문장과 이어지는 논리적 관계 설명**을 적고, **각 문단의 마지막 페이지에는 ‘주제 (Topic)’와 ‘제목 (Title)’의 작성 칸**을 둡니다.
- 교과서는 실제 입력이 1문단뿐이면 **‘Paragraph 1’ 표시 없이** 연속된 한 지문으로 보여 줍니다. 2문단 이상이면 문단별 표시가 나옵니다. 모의고사는 문단 표시 대신 **18번, 19번 … 45번** 중 입력한 번호만 표시합니다.
- **STEP 1:** 모든 문장의 해석, 문장 사이 논리 관계 빈칸, 문단별 내용확인과 한국어 O/X.
- **STEP 2:** 모든 문장에 단어 빈칸 2~3개를 기본으로 배치합니다. `Sincerely,`처럼 단어가 하나뿐인 짧은 문장은 가능한 단어만 빈칸으로 만듭니다. AI가 선택한 빈칸 단어의 대소문자가 원문과 달라도 원문의 철자를 기준으로 처리합니다.
- **STEP 3:** 모든 문장의 어법 선택과 근거 작성 두 줄.
- **STEP 4:** 문단 나열. 한 문제의 제시문과 답안 칸을 **한 페이지에 모두** 넣습니다. 길면 독립적인 여러 문제로 나눕니다.
- **STEP 5:** 문장 나열. 문장 수를 3~4개로 고정하지 않고 한 페이지에 담을 수 있는 분량까지 한 문제로 묶습니다. 긴 지문은 각 문제의 문장이 한 페이지 안에 들어가도록 독립 문제로 나눕니다.
- **교사용:** STEP 1 해석·연결·내용확인, STEP 2 빈칸, STEP 3 어법, STEP 4 문단 나열, STEP 5 문장 나열 순서로 답을 정리합니다.

## 시그니처 캐릭터와 그림 기준

`assets/mascot_reference.png`는 사용자가 제공한 예시 속 두 안내자만 배경 없이 정리한 기준 이미지입니다. 새로운 삽화에는 이 이미지만 참조로 보냅니다. 따라서 예시의 전쟁·문화재 배경이 다른 지문으로 옮겨가는 일을 줄였습니다. 텍스트 분석 단계에서 **각 컷의 장면 설명을 지문 내용만으로 먼저 만들고**, 그 설명과 해당 영어 문장을 함께 이미지 생성에 보냅니다. 3:1 가로형 그림의 **3컷을 기본**으로 하며 4문장은 1+1+2, 5문장은 1+2+2문장을 세 컷에 담습니다. 그림의 내용은 생성형 모델의 결과이므로 인쇄 전 지문과 맞는지 확인하세요.

삽화는 READING에만 들어갑니다. 생성형 이미지의 세부 외형과 장면 묘사는 매번 달라질 수 있으므로 인쇄 전 확인하세요. 일시적인 텍스트·삽화 실패는 자동 재시도 후 **실패한 항목 다시 만들기**로 추가 요청할 수 있습니다. API 키·한도·결제 등 설정 오류는 설정을 바로잡아야 합니다. 서버 재시작 시 작업 결과와 삽화가 사라지므로 PDF 또는 초안 JSON을 저장해 두세요. 긴 지문이나 많은 번호를 선택하면 생성 시간과 API 비용이 늘어납니다.

검증은 `npm test`로 실행합니다.
